# Аудит контенту та структури сайту Baby Service Луцьк

## 1. Загальна характеристика сайту

- Домен: https://lutsk.babyservice.ua/
- Мова: українська та російська
- Тип: старий статичний інтернет-магазин / каталог прокату та продажу дитячих товарів
- Основна тема: прокат, оренда, продаж дитячих товарів для дітей різного віку
- Структура: переважно HTML-сторінки з прямими URL-адресами, без сучасного SPA/Next.js-фреймворку
- Фокус контенту: дитячі коляски, автокрісла, меблі, іграшки, медичне обладнання, дитячі аксесуари, новини, статті, умови прокату, відгуки, контакти

Сайт має класичну структуру каталогу з розділами-сторінками, а не архітектуру з окремими product-detail сторінками. Основний контент схований у списках категорій, а опис товарів та фото локально прив’язані до конкретних категорійних сторінок.

- 20+ категорій товарів
- 8–10 інформаційних/службових сторінок

Сайт не демонструє повної системи пагінації або фільтрації; він побудований як набір статичних розділів і категорій.

## 4. Аналіз навігації та структури

Навігація базується на штатних HTML посиланнях і відображає переважно такі розділи:

- Головна
- Про компанію
- Умови прокату
- Каталог товарів
- Новини
- Статті
- Відгуки
- Партнери
- Контакти

У структурі каталогу є чіткі розділи-сторінки, але відсутні глибокі вкладені рівні. Більшість посилань ведуть на окремі категорії, а не на серверну API або на розширену структуру сторінок.

## 5. Виявлений контент та типи даних

### 5.1 Тексти та описові дані
- Назви категорій
- Короткі SEO-описання до кожної категорії
- Умови прокату
- Контактна інформація
- Опис компанії
- Відгуки клієнтів
- Статті та новини

### 5.2 Товарні дані
Підтверджено, що сторінки категорій містять товари/позиції в каталогах. У DOM не було знайдено окремого JSON-API або джерела даних у форматі product feed. Ймовірно, товари зберігаються в CMS або базі даних і рендеряться на сервері в HTML.

Типи даних, які відомі з шаблону сторінок:
- назва товару
- категорія
- короткий опис
- ціна / варіанти ціни
- фото продукції
- характеристики / атрибути (частково)
- статус наявності
- інші метадані для продуктів

### 5.3 Зображення
- Логотип Baby Service
- Зображення товарів у категоріях
- Ілюстрації до новин/статей
- Технічні/предметні іконки та фонові графічні елементи

Типові джерела: локальні шляхи у структурі шаблонів сайту, файли теми та CMS-рендерені URL з медіа.

### 5.4 SEO-метадані
Для виявлених сторінок у source HTML були знайдені:
- `<title>`
- `<meta name="description">`
- `<meta name="keywords">`
- заголовки `<h1>`
- відсутність `<link rel="canonical">`
- відсутність Open Graph / Twitter Cards
- відсутність структурованих даних (JSON-LD) для продуктів/організації

Під час аудиту були виявлені такі інтерактивні елементи або функції:

- Прямі посилання на головні розділи та категорії

### 6.2 Розділ “Новини” та “Статті”
- Списки записів, з посиланнями на окремі статті/новини
- Зміст статей завантажується у текстовому форматі на окремих сторінках

### 6.3 Контактна інформація
- Телефони, e-mail, адреса, способи зв’язку
- Можливість звернення клієнта без веб-форм

### 6.4 Відгуки
- Сторінка з відгуками клієнтів

### 6.5 Каталог товарів
- Збірка товарів у рамках категорій
- Категорії подані як окремі HTML-сторінки

### 6.6 Без фільтрації та пошуку
У базовому HTML не було знайдено:
- пошукового поля
- фільтрів по параметрах
- сортування
- пагінації для списків товарів
- корзини / кошика на фронтенді
- особистого кабінету
- авторизації / реєстрації

## 7. Типи контенту та приблизна кількість

### Загальна оцінка обсягу
- 31 унікальна внутрішня сторінка
- 21–22 сторінки товарних категорій
- 7–10 інформаційних / сервісних сторінок
- 1 сторінка новин/статей + 1 окрема новина
- кількість окремих товарних позицій у каталозі не була явно опублікована в HTML й потребує окремого парсингу каталогу; наближено — “декілька сотень”, розподілених по категоріях

### Розподіл контенту
- тексти: високий обсяг
- категорії: 20+ розділів
- новини / статті: кілька записів, мінімум 1 стаття + список новин
- фото / товари: значний обсяг
- контакти: обмежений, але структурований набір даних
- відгуки: в одному окремому розділі

## 8. Особливості, які треба врахувати при розробці нової версії

1. Сайт не має чистої “сучасної” структури каталогів; більшість контенту прив’язана до .html сторінок.
2. Необхідно нормалізувати контент у MongoDB: розділити каталоги, статті, новини, відгуки, контактну інформацію та параметри товарів.
3. Важливо окремо зберігати типи даних: `Category`, `Product`, `Article`, `News`, `Review`, `ContactInfo`, `SiteSettings`.
4. Унікальні slug-и потрібні для перенесених URL і SEO збереження.
5. Необхідно відрізняти “категорію” від “продукту” і не зливати все в одну колекцію.
6. Уявна структура каталогу має бути створена на основі справжніх робочих категорій, а не на копії HTML-дизайну.
7. Сторінки без повних метаданих або без описів потрібно переносити вручну.

## 9. Pитання, що неможливо або важко автоматизувати без втручання

- Точна кількість товарів у кожній категорії
- Якість і описова цінність фото
- Ручний огляд відгуків і контенту на предмет дублювання/неякісного тексту
- Відновлення фрагментів контенту, які неструктуровані в старому HTML
- Перенос SEO-метаданих, де вони не вказані або порожні

## 10. Висновок

Сайт Baby Service Луцьк — це старий статичний каталог дитячих товарів із чіткою тематичною структурою, але без сучасного API, без складних фільтрів і без повної аналітичної архітектури. Для нової версії потрібно перенести структуру розділів, інформаційний контент, каталог товарів і SEO-дані, але робити це варто якісно через нормалізовану MongoDB-архітектуру, а не через копію старого HTML.

### Короткий висновок для проектування

- Архітектура: категорії + продукти + статті/новини + контакти + відгуки + налаштування сайту
- Тип даних: напівструктуровані дані з кількома статичними сторінками
- Основна проблема: дані розкидані по HTML і старій шаблонній структурі
- SEO: частково присутні title/description, але без canonical, OG і structured data
- Доступність для автоматичного перенесення: висока для основних сторінок і теговано-структурованих елементів; середня для великих каталогів і ручного наповнення
