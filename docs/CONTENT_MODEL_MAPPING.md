# CONTENT_MODEL_MAPPING.md

## 0. Актуальний стан проєкту

У поточному коді відсутня повна доменна модель для Baby Service. Замість неї є загальна модель `Item`, яка описує простий товар, а також `User` і `Article`.

Це важливо, бо старий сайт має значно ширшу структуру: категорії, товари, інформаційні сторінки, новини, статті, відгуки, медіа, глобальні налаштування та мову. Тому поточну цільову мапу контенту слід розглядати як рекомендацію для реалізації, а не як фактичний стан проєкту.

## 1. Мета документа

Цей файл описує відповідність між старим контентом вихідного сайту та новими MongoDB-моделями. Мета — зберегти структуру, типи контенту та навігаційну логіку без копіювання старого дизайну.

## 2. Таблиця відповідності

| Вихідний контент | Тип сторінки / джерело | Модель MongoDB | Коментар |
|---|---|---|---|
| Головна сторінка | Статична сторінка | Page або SiteSettings | Головна сторінка є комбінованою сторінкою; для нової архітектури варто зберігати її як Page + дані з SiteSettings |
| Категорії товарів | Каталог / розділи | Category | Ключовий механізм структури каталогу |
| Список товарів у категорії | `/catalog/[categorySlug]` | Product + Category | Сторінка категорії містить список товарів, але окремий товар має бути окремим документом Product |
| Сторінка товару | `/catalog/[categorySlug]/[productSlug]` | Product | Обов’язково передбачити окрему сторінку одного товару |
| Про компанію | /about.html | Page | Інформаційна сторінка |
| Контакти | /contacts.html | Page або SiteSettings | Контактна інформація теж може бути збережена в SiteSettings |
| Умови прокату | /usloviya_prokata.html | Page | Статична інформаційна сторінка |
| Партнери | /partners.html | Page | Статична сторінка |
| Відгуки | /comments.html | Review | Модель окремого контенту |
| Новини | /novosti.html + статті в /novosti/* | News | Окремий тип контенту |
| Статті | /staty.html + статті у розділі | Article | Інформаційні статті |
| Логотип / зображення | Всі сторінки | Media | Загальна модель медіафайлів |
| SEO title / description | HTML head | SiteSettings + Category + Product + Page + News + Article | Зберігати в базі окремо для кожного типу |
| Список посилань на інші міські сайти | Головна сторінка | SiteSettings | Можна зберігати як зовнішні посилання або статичний блок |
| Про нас / короткий опис | Головна сторінка | SiteSettings або Page | У залежності від того, чи це глобальна інформація чи повна сторінка |
| Ціни / типи цін | Категорійні списки | Product.price | Обов’язково зберігати sale + rent |
| Характеристики | Товари | Product.attributes | Вкладений масив атрибутів |
| Фотографії | Товари / новини / статті / сторінки | Media + Array<ObjectId> | Зберігати окремо, посилання в документі |
| Порядок відображення | Категорії / продукти | Category.displayOrder, Product.displayOrder | Для сортування контенту |
| Статус публікації | Всі типи контенту | Draft/Published | Потрібен для адмін-панелі |

## 3. Подробиці по ключовим типам контенту

### 3.1. Categories
Старі категорії:
- ваги
- автокрісла
- коляски
- кроватки
- молоковідсмоктувачі
- укачуючі центри
- ергокрани / рюкзаки / переноски
- ходунки / штанці
- ліжечка / манежі
- медичне обладнання
- радіоняни
- стільчики для годування
- розвивальні килимки
- вуличні розваги
- велосипеди / беговели / самокати
- туристичне спорядження
- пеленальні столи
- стрибунці
- карнавальні костюми
- розвивальні іграшки
- меблі для івенту

Всі ці розділи мають бути збережені як `Category` з унікальними slug і мідлатиною.

### 3.2. Products
Товари є внутрішньою складовою категорій. Тому в новій схемі вони мають бути окремою `Product`-колекцією, навіть якщо історично вони існували лише як частина HTML-сторінок.

### 3.3. Page
Сторінки:
- Про компанію
- Контакти
- Умови прокату
- Партнери
- інші статичні майбутні сторінки

Вони відповідають `Page`.

### 3.4. News
Новини містять список новин та окрему новину. Це окремий тип `News` з окремим `slug` та `publishedAt`.

### 3.5. Article
Статті сайту мають структуру, схожу на новини, але логічно відокремлюються, оскільки у старому сайті вони були окремим розділом.

### 3.6. Review
Відгуки — окремий тип, який не варто змішувати з `Page` або `News`.

### 3.7. SiteSettings
Дані, які є глобальними для всього сайту:
- назва сайту
- логотип
- контакти
- адреса
- соціальні мережі
- базова локалізація
- загальні SEO налаштування

## 4. Принцип мапінгу старого URL в нову модель

| Старий URL | Підходяща модель | Коментар |
|---|---|---|
| /about.html | Page | `pageType: 'about'` |
| /contacts.html | Page або SiteSettings | За потреби винести в глобальні налаштування |
| /usloviya_prokata.html | Page | `pageType: 'terms'` |
| /partners.html | Page | `pageType: 'partners'` |
| /comments.html | Review index page / list | Може бути окремим списком або окремою сторінкою |
| /staty.html | Article list page | Список статей |
| /novosti.html | News list page | Список новин |
| /ru/ | Locale root | Мова та перенаправлення |
| /avtokrisla.html | Category | Категорія продуктів |
| /kolyaski.html | Category | Категорія продуктів |
| /... | Category | Решта категорій |

## 5. Важливі нюанси

- Не всі старі HTML URL будуть прямим відображенням нових URL; частина з них має бути збережена як redirect map.
- Для нових сторінок краще використовувати `slug` на основі категорії/сторінки, а старі `.html` URL переводити в `redirects`.
- Окремі сторінки товарів є обов’язковим елементом нової архітектури, навіть якщо старий сайт не мав для них окремих адрес. У новій схемі кожен товар має отримати унікальний `slug` і маршрут `/catalog/[categorySlug]/[productSlug]` або `/ru/catalog/[categorySlug]/[productSlug]`.
- Якщо старі сторінки мали чисто статичну роль, їх можна перенести до `Page` без втрати сенсу.
- Для відгуків важливо мати окремий рейтинг і дата публікації.

## 6. Висновок

Найбільш логічна мапа така:

- Category → розділи каталогу
- Product → товари
- Page → статичні сторінки
- Article → статті
- News → новини
- Review → відгуки
- Media → графіка та фото
- SiteSettings → глобальні параметри
- User → адміністратори та редактори

Таким чином вдається зберегти бувший функціональний контент, не розпорошивши його по одному загальному контейнеру.
