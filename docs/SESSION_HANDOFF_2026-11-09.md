# Передача контексту сесії — 09.11.2026

## A. Загальний стан

- **Стек:** Next.js 14 App Router, React 18, TypeScript, Mongoose і MongoDB; CSS/SCSS модулі. Версії пакетів і реалізацію надалі звіряти з `package.json` та кодом.
- **Структура:** маршрути в `src/app`, UI-компоненти в `src/components` та `src/(components)`, Mongoose-моделі в `src/models`, сервісний шар у `src/services`, підключення/локаль у `src/lib`, міграційні матеріали в `tools/content-migration`.
- **Маршрутизація:** у коді є українські маршрути в корені та окремі російські маршрути в `src/app/ru`. Категорії й товари мають сторінки `/catalog/[categorySlug]`, `/catalog/[categorySlug]/[productSlug]` та їх `/ru/...` аналоги. Є також сторінки про компанію, контакти, партнери, умови, новини, статті й відгуки. Legacy redirects, canonical і hreflang не підтверджені як реалізовані.
- **Mongoose-моделі:** у `src/models` є `Article`, `Category`, `Media`, `News`, `Page`, `Product`, `Review`, `SiteSettings` і `User`; `src/models/index.ts` їх експортує. Старі загальні API-моделі теж лишаються в `src/app/api/models` і не є заміною нових доменних моделей.
- **Сервіси:** є `category.service.ts` і `product.service.ts`. Вони читають опубліковані дані та фільтрують локалізовані поля; робота цих шляхів із реальними записами не підтверджена.
- **Локалізація:** `Locale` має значення `uk | ru`; українська — без префікса, російська — під `/ru`. Маршрути й сервісні запити вказують на locale окремо. Реальна відповідність сторінок legacy сайту між мовами не доведена лише наявністю парних URL.

## D. Результати dry-run

- **Дозволений набір із README та `ALLOWED_URLS`:**
  - `https://lutsk.babyservice.ua/avtokrisla.html`
  - `https://lutsk.babyservice.ua/ru/avtokrisla.html`
  - `https://lutsk.babyservice.ua/avtokrisla/avtokreslo_adbor_capri.html`
  - `https://lutsk.babyservice.ua/ru/avtokrisla/avtokreslo_adbor_capri.html`
- Нових HTTP-запитів і повторного запуску extractor не було.
- Збережений manifest містить 2 категорії, 2 товари та 4 медіазаписи. Validation report рахує **8 записів: 8 `accept`, 0 `review`, 0 `reject`, без issue-кодів**. Є лише статичні blockers; вони не впливають на статус записів.
- У медіа є логотип і одне фото товару, повторені для обох мов; дублікати не позначені. Сторінки/статті не представлені у звіті.
- **Місце виникнення:** `tools/content-migration/run-dry-run.mjs`: `getPriceText` шукає перше слово з широкого переліку по всьому тексту сторінки, а не витягує конкретний блок ціни; `parseProductPage` записує `isConfirmed: false`, `amount: null`, `periodDays: null`; `validateRecord` не переводить `rental` із `isConfirmed: false` у `review` і попереджає про ціну лише для `unknown`. У `candidate-manifest.json` видно сторонню навігацію/контакти й пошкоджене кодування в `rawText`. Тому обидва товари отримали `accept` з непідтвердженим pricing та невідомою доступністю.
- **Суперечність контракту:** `CONTENT_MIGRATION_MANIFEST_DESIGN.md` визначає непідтверджені дані як `review` і застерігає від автоматичного злиття мовних сторінок. Фактичний валідатор не перевіряє достатньо цих умов: він приймає товар без підтверджених pricing/availability та медіа без перевірки дублікатів.
- `buildReport` у `run-dry-run.mjs` рахує лише `categories`, `products` і `media`; `pages` порожній, Articles не формуються. Отже, підсумок 8 — це статуси цих 8 кандидатів, а не оцінка повноти міграції.
- **Мовна відповідність не доведена:** у `run-dry-run.mjs` `getLocale` визначає мову лише за `/ru/`, `getSourcePageKey` створює ключ джерельної сторінки, а `getEntityKey` формує ключ типу й останнього нормалізованого slug. Для uk/ru записів встановлено `localeMatch: "confirmed"` на підставі однакового slug/структури URL, без незалежного evidence для тотожності сутності. `sourcePageKey` ідентифікує джерельну сторінку/мову, а `entityKey` має означати логічну сутність; фактично другий ключ тут є лише slug-групуванням і може злити різні записи.
- У кожному мовному кандидатові назва та slug є лише для його мови. Зокрема, кандидат ru сам по собі не має обов’язкового `slug.uk` з контракту Mongoose; окремі locale-сторінки не можна вважати готовими документами `Product`/`Category` без підтвердженого об’єднання.
- **Історія URL:** у `candidate-manifest.json` зберігаються `legacyUrl`/`normalizedUrl` поточного джерела, але немає `previousLegacyUrls` і доказу перенаправлення. `sourcePageKey` побудований зі slug у `getSourcePageKey`, тому зміна slug/URL змінить ключ; відповідність старих та нових адрес має лишатися review до окремої перевірки. `URL_REDIRECT_MAP.md` — попередній план, не реалізований redirect map.
- **Розбіжність URL у README не відтворена:** російський товар у README та manifest має однакову адресу `https://lutsk.babyservice.ua/ru/avtokrisla/avtokreslo_adbor_capri.html`. README також містить правильну команду `node tools/content-migration/run-dry-run.mjs`. У перевіреній копії конкретної відмінності між цими двома URL немає.
- `candidate-manifest.json` і `validation-report.json` читаються. У них не знайдено полів із назвами `password`, `secret`, `token`, `api_key`, `authorization` або `cookie`; ця перевірка маркерів не гарантує відсутності довільно замаскованих секретів. У raw price text є публічні контактні дані сайту та пошкоджений текст.
- Обидва JSON — **untracked і не ігноруються Git**; `git check-ignore` правил для них не показав. Файли не видаляти. У `docs` і `tools/content-migration` не виявлено файлів понад 1 MB.

## G. Відкриті проблеми за пріоритетом

### Blocker

- Не використовувати 8 `accept` як дозвіл на імпорт: звіт не реалізує контрактний поріг доказів і пропускає невирішені поля.
- Немає реального контенту в MongoDB; немає підтвердженого джерела повного legacy export чи повної таблиці відповідностей мов.

### High

- Парні сторінки uk/ru вважаються однією сутністю за однаковим slug без незалежних доказів; розрізняти `sourcePageKey` (конкретна сторінка) та `entityKey` (підтверджена сутність).
- Pricing extraction захоплює нецільовий текст/пошкоджене кодування; `amount` і `periodDays` порожні, ціна не підтверджена, але запис `accept`.
- Кандидат лише для `ru` не має обов’язкового `slug.uk` моделі; потрібне підтверджене locale-об’єднання або статус `review`.

### Medium

- Не збережена історія зміни URL (`previousLegacyUrls`), а redirect-map лишається гіпотезою.
- Один логотип і те саме фото повторюються для двох мов; дедуплікації та перевірки сутностей/медіа недостатньо.
- Старі документи про модель і архітектуру містять фактично хибні твердження про відсутність нових моделей/локалізованих маршрутів.

### Low

- `URL_REDIRECT_MAP.md` має уточнити, що сторінки маршрутів існують, але redirects/canonical/hreflang не підтверджені.
- Повідомлена розбіжність російського товарного URL з README у поточних артефактах не відтворюється; якщо вона спостерігалася в іншій копії/версії, потрібне порівняння саме тих файлів.

## H. Наступний етап

Один невеликий етап: виправити та протестувати **лише правила статусу dry-run** на збережених JSON/HTML fixtures (без HTTP і MongoDB), щоб непідтверджений pricing, locale match, обов’язкові локалізовані поля та нерозв’язані зв’язки завжди давали `review`, а звіт узгоджено рахував ці записи. Не починати масову міграцію.
